# 初期公開の運用

2026-10-03、運営者の「人の審査は本番公開後に行い、ネット上の資料で整合性を取りつつ公開する」という指示に基づく。公開先行の許可と内容の人による審査を別に扱う。

## 配信する内容

- ヒューム・ロック・デカルトの36項目。概念は著者・著作の文脈ごとに区別する。
- 短い日本語要約、考え方の帰属、留保、出典の位置、原著とオンライン版・翻訳・編者の違い。
- 関係は編集上の案内として表示し、歴史的影響・同一性を自動的に推論しない。
- 年表は根拠のある著作の刊行情報に限定する。未照合の生没年を加えない。

公開元の草稿は `content-review/*-reviewed.json`。草稿を人の承認済みに書き換えない。全文は保存・転載しない。

## データと編集

初期公開はDBを必要としない、版を固定した読み取り専用のデータ配信を使う。制作元JSONとmanifestはGitHubに保存し、生成時に参照整合性・ハッシュ・審査状態を検査する。公開ページ、検索、関係図、年表、根拠は同じ可視集合を使う。

`NOEMAP_RUNTIME_FILE` を設定したローカル起動だけ、既存の架空DB・編集アカウントを使う。本番にこの変数を設定しない。公開モードは `/editor` の画面を404、編集POSTを403にし、DB接続情報やローカルアカウントを要求しない。

DBを使う編集基盤の既存レビュー・公開grantは変更しない。永続DBと本番編集者認証への移行は別工程で行う。初期公開の許可をDBの人によるレビュー記録に流用しない。

## 訂正と撤回

1. 元の内容を訂正する場合は制作元JSONを編集する。差分を確認し、`node scripts/build-public-release.mjs --print-source-hashes` で読取専用のハッシュ一覧を取得する。manifestの版IDと `batch_files` の該当SHA-256を更新する。人の確認が未実施ならpendingを維持する。刊行metadataを変更した場合は、年表生成の根拠も再照合する。
2. 出典を取り下げる場合はmanifestの `withdrawn.sources` に元の資料IDを追加する。項目・記述・関係もそれぞれの配列で撤回できる。
3. `npm run content:release` と `npm run test:release`、型検査、ビルドを通す。
4. 公開リポジトリへ反映して再配置する。新しい公開版への配置完了後、ページ・検索・関係図・年表・根拠を確認する。過去に取得済みの画面や外部のコピーを消す操作ではない。

一つの出典だけが撤回されても、別の出典を使う独立した内容まで消さない。複数の根拠や留保に依存する内容は、その依存が欠けた状態で表示しない。

## 公開と復旧

実装の開発履歴は `noemap/noemap` のPR #2に保存する。Vercelの既存プロジェクト `noemap.com` は `noemap/noemap.com` と連携しているため、検証した実装をこの公開リポジトリへ保存する。`vercel.json` でNext.js・ビルドコマンド・出力先を指定する。

公開はVercelのGit連携を使う。mainへ反映したコミットSHAとVercel配置ID、実URLでの検証結果を保存する。配置完了・実URLでの動作確認までは「本番公開済み」と記録しない。

復旧時は直前の動作確認済みのコードとmanifestに戻して再配置する。撤回が必要だった資料を含む古い版へ戻す場合、その撤回を新しい復旧版にも反映する。初期公開には更新可能な本番DBがないため、DBのバックアップ完了や復元試験済みとは扱わない。
