1. 目的と前提
NOEMAPは「人間とは何か」を中心に、哲学・宗教・歴史・心理学・社会学・生物学・脳科学を横断する知識探索サイト。人物・概念・思想・出来事・時代・問いを接続する。名称はNOEMAP。NORMAPは誤記。
問いを入口に、複数の見方を比較し、つながりの理由を理解できることを主価値とする。収益化は副次的。日本語・スマートフォン優先。GitHubでソース管理し、Vercelへデプロイする運用を希望。
体験の中心は「別々の知識がつながる面白さ」。主な読者は、専門知識はないが人間・思想・社会に知的好奇心がある人。各記事だけでも理解でき、関連する記事を辿ると理解が深まる構成にする。
単なる用語集や汎用AIチャットではなく、編集した知識と出典を辿る体験を作る。広い分野を扱うが「人間を理解する」という編集軸を保つ。
2. 実装範囲と段階
Phase 1：知識探索の初期版
ホーム、問い一覧、テーマ一覧・詳細、問い詳細、人物・概念等の詳細、検索、ページ内の小規模な関係マップ、出典、サイトの説明・編集方針を実装。
最初から課金・認証・AI APIを必須にしない。関係データと記事を一元管理し、後で接続可能な境界を作る。
今回の最優先着手は、4章の入口UIと、実際のURLを持つ個別の問いページ、その往復導線。まずここをレビュー可能な状態にし、一覧・検索・人物・概念・関係マップはその基盤に接続する。既存実装がある場合は必要箇所を変更し、完成済みの機能を作り直さない。
Phase 2：保存と学習継続
アカウント、ブックマーク、探索履歴、マイノートを追加。初期版で匿名保存を提供する場合は端末内保存と明記し、会員保存と区別する。
Phase 3：出典付きサイト内AI
記事解説・比較・反論・次のページ案内。少数の無料体験枠を設け、利用量と原価を測定する。
Phase 4：会員プラン
十分に多いAI利用枠、会話保存、ノート連携等を候補とする。料金と上限は実測後に確定。無条件の完全無制限を初期仕様にしない。
初期着手はPhase 1のみ。将来機能のボタンを実機能のように表示しない。公開・外部契約・課金開始は本書だけで承認済みと解釈しない。

初期ナビゲーションは「問い」「テーマ」「人物・概念」「検索」。ホームへはロゴから移動。「人物・概念」の一覧内部で他の種類も扱う。哲学等の学問分野は、テーマとは別の分類・絞り込みとして使う。「学問から探す」入口はテーマカードより下、または一覧の絞り込みとして置ける。初期から学問ごとにホームを分割しない。
4. ホームの表示順
1. ロゴ「NOEMAP」、主見出し「人間とは何か。」、補助文「気になる問いから、知識のつながりを辿る。」を表示。
2. 「どこから考えてみる？」の下に、8つの大テーマのカード。今回のプレビューで合意した主導線であり、最初の画面の中心にする。
3. 検索欄。問い・人物名・概念名を入力できる。ヘッダーにも検索への入口を置ける。検索でカード群を下へ押し出さない。
4. 個別記事に直接進める問いの案内を少数配置。入口カードと同じ説明を大量に繰り返さない。
5. 編集した探索ルート。「他人との比較 → 承認 → 自己」等。ルートの解説を添える。
6. 新規・更新されたページ。
7. 出典と複数の立場を大切にする編集方針への案内。
巨大なグラフを最初の画面に置かない。ログイン前提の導線を主役にしない。
4.1 大テーマのカード
安定したID	表示名	添える身近な問い	アイコン案
body	からだと生命	生きているってどういうこと？	activity
mind	こころと意識	こころはどこにある？	brain
self	自分と他者	自分らしさって何だろう？	users
society	社会と文明	なぜ人は社会をつくる？	landmark
ethics	善悪と正義	正しさは誰が決める？	scale
happiness	幸福と意味	幸せに生きるってどういうこと？	sun
death	死と信仰	死をどう受け止める？	hourglass
knowledge	知識と真実	本当だとどう分かる？	compass


カードの基本は「大きめの線画アイコン＋短いテーマ名＋具体的な問い」。アイコンだけで意味を伝えようとしない。カード全体を押せるようにし、色数を抑え、余白・文字のコントラスト・大きさを優先する。
スマホは2列、PCは4列。参考プレビューでは600px以下を2列としている。既存サイトのブレークポイントは尊重しつつ、320pxでも2列のカードが読みやすく収まることを実装時に確認する。カード内の問いは改行してよい。カード自体の横スクロールは使わない。
暖かい明るい背景、白系の面、濃い本文、落ち着いた青系のアイコンを基本とする。ダークモードがある場合も同じ階層・コントラストを保つ。参考の比率はテーマ名14px、補助文12px、アイコン30px程度。既存の文字サイズ設定に合わせて調整可能。写真を必須にしない。
4.2 入口の階層と、押した後の動作
階層	例	操作結果
大テーマ	こころと意識	小テーマの問いを、そのカードの列のすぐ下に開く
小テーマ	意識とは何か？	さらに具体的な問いへのリンクを、押した項目の直下に開く
個別の問い	AIに意識は生まれる？	その問いの個別記事URLへ直接移動する


通常経路は「大テーマを開く → 小テーマを開く → 記事へ」の3タップまで。展開は2段階で止める。末端の問いのクリック後に、もう一段の問い一覧、本文の折りたたみ、確認画面を挟まない。
実装例：ホーム → 「こころと意識」を押す → 「意識とは何か？」を押す → 「AIに意識は生まれる？」を押す → /questions/ai-consciousness を表示。slugは例示であり、既存の公開URLがあれば尊重する。
「小テーマ」は入口で問いを整理するまとまり。大きな問い自体を読みたい読者のために、「この問いの概要を読む」からその概要記事へ直接進める。細かい問いを選ぶことを必須にしない。検索結果や本文中のリンクからは、個別記事へ直接入れる。
4.3 直近に開くことを優先する
- 大テーマの展開領域は、選んだカードを含む行の直後に配置する。PCで最上段のカードを押したときに、全8カードの後ろへ表示しない。
- 小テーマの問いは縦に並べる。押した小テーマの直下、その次の小テーマより前に子リンクを挿入する。小テーマ全4件の下に一括で表示する方式は採用しない。
- 小テーマを開いた直後に子リンクが見えるようにする。重複する題名・長い説明・パンくず・大きな余白を子リンクより上に積まない。
- 選択中の項目は背景・境界線と矢印で状態を示す。展開ボタンは下向き矢印、個別記事へのリンクは右向き矢印を使い、動作を区別する。
- 同じ展開ボタンをもう一度押すと閉じる。同階層では一つだけ開く。テーマを切り替えたら以前の子選択を整理し、現在の文脈が分かるようにする。
- 原則としてタップ位置を保つ。自動スクロールで遠くへ飛ばして展開を見せる方式を主な解決策にしない。必要な場合だけ、新しい領域を最小限の移動で見せる。
4.4 個別記事への移動と、戻る操作
末端の問いは実際のリンクとして実装する。Next.jsを使う場合はLink等で実在する /questions/[slug] へ移動し、見た目だけの画面差し替えやダミーのハッシュURLを本番仕様にしない。
各記事は直接URLを開ける、更新できる、共有できること。ブラウザの戻る操作でホームへ戻ったときは、開いていた大テーマ・小テーマとスクロール位置を復元する。操作ボタンとしても「問いの一覧に戻る」を用意する。記事URLへ直接来た人には、関連するテーマ一覧やホームへ戻る有効なリンクを用意する。戻るために、空の履歴へ一律で back() だけを実行しない。
開閉状態はURLクエリ・履歴状態・セッション等で扱えるが、共有された記事URLを開くために、先にホームで選択していることを条件にしない。テーマ・グループ・記事のIDを保持し、表示文言から状態を判定しない。
4.5 心理学・宗教などを増やすときのルール
大テーマは「人間について何を考えたいか」の入口。学問分野は「どの視点から理解するか」の分類として、別に管理する。
学問・分野	関わる大テーマの例
心理学	こころと意識／自分と他者／幸福と意味
宗教・宗教学	死と信仰／善悪と正義／社会と文明
歴史学	社会と文明／善悪と正義／知識と真実
生物学・脳科学	からだと生命／こころと意識／自分と他者


学問を追加するたびに最上位カードを増やしたり、トップを作り直したりしない。問い、解説の視点、人物・概念・歴史との関係を増やす。同じ問いを複数テーマから案内してよい。例えば自由意志は「こころと意識」「善悪と正義」の両方から、同じ記事へつなぐ。コピー記事やテーマ別の重複URLを作らない。
現在の8テーマは編集上の暫定分類。内容が増えて分類が難しくなったら名称や分け方を見直せる。操作・カードの見せ方は維持し、ID・URLの継続性を考慮して分類を育てる。
4.6 公開コンテンツと操作見本の区別
参考HTMLの問いや本文は画面構成を示す編集候補・表示例。出典確認済みの記事として本番に移植しない。公開入口には公開済みの記事へ到達するリンクだけを出す。未整備のテーマを表示する場合は準備中と分かる状態にするか、公開時には非表示とする。存在しない記事へのリンクは置かない。
非公開の開発プレビューで全8テーマの操作を見せる必要がある場合は、公開記事データと分離したデモデータを使う。出典のないダミー本文を公開記事として登録しない。
5. ページの共通構造
問い詳細
タイトル、短い導入、要点、問いの輪郭、主な見方の比較、一致点と対立点、根拠と限界、関係マップ、次に読む3〜5件、関連書籍、出典、更新日。
個別記事では入口の分類選択をやり直させない。冒頭から本文を読めることを優先する。まず具体例と要点、その後に複数の見方、最後に関連する知識を見せる。関係マップや関連記事には「なぜつながるか」の説明を添える。記事の理解に、何度も別ページへ移動することを必須にしない。
比較表の列は「見方／説明の中心／説明できること／限界」。結論が定まらない問いに一つの答えを強制しない。日常例と学術的な主張の区別を明示。
人物詳細
何を考えた人物か、生没年・活動地域（検証できた場合）、主な問い、主要概念・著作、影響と批判、関連ページ、出典。
人物の思想を短いキャッチコピーだけで断定しない。
概念・思想詳細
短い定義、成立背景、具体例、近い概念との違い、代表的立場、批判と限界、関連する問い、出典。
出来事・時代詳細
時間・場所、背景、何が起きたか、人間観や思想との関係、複数の解釈、関連人物・概念、出典。
すべてのページでパンくず、種類、テーマ・分野、更新日を表示。長い本文は目次を設ける。

人物・概念は15問を支えるものから追加。記事数の水増しをしない。まず出典確認済みの代表的な問い1本、人物1本、概念1本で画面とデータ構造を検証し、その後拡充する。未完成ページはdraftにし、一覧・検索・サイトマップから除外。
7. 知識グラフの仕様
ノード種類：question / person / concept / idea / event / period。
テーマと学問分野はノード種類とは別の分類。
関係はsourceId、targetId、type、短い説明、出典を持つ。有向関係の方向を定義して統一する。
type	向き
addresses	人物・思想・概念 → 問い（この問いを扱う）
advocates	人物 → 思想・概念（主張・支持する）
criticizes	人物・思想 → 批判対象
influenced_by	影響を受けた人物・思想 → 影響元
contrasts_with	対比対象同士。逆向きを重複保存せず表示時に双方向扱い
contextualized_by	人物・思想・概念 → 出来事・時代（成立背景）


「関連あり」だけで結ばない。関係の説明と根拠を保存する。解釈による関連はその旨を明記。
初期版は現在のページから1段階、最大8ノード程度。ノード選択で説明と記事リンクを表示。拡張操作で次の関係を探索。スマホでは同じ情報を関係リストでも読めるようにし、グラフ操作を必須にしない。
8. データ設計
Node共通：id（不変）、slug、type、title、aliases、summary、themeIds、disciplineIds、status（draft/published）、publishedAt、updatedAt、sourceIds、seoTitle、seoDescription。
種類固有の本文と項目は型別に保持。本文はMDXまたは同等の構造化コンテンツ。
Source：id、title、author、kind（原典・研究論文・公的資料・二次資料等）、urlまたは書誌情報、刊行年、参照箇所、確認日。
Claim：id、nodeId、本文の対応箇所、sourceIds、区分（実証的知見・哲学的議論・宗教的教え・編集上の解釈）、限界説明。
Relation：id、sourceId、targetId、type、explanation、sourceIds、interpretive。
Theme：id、slug、title、description、表示順。
入口の追加データ：
- ThemeにshortLabel、prompt、icon、order、公開表示の設定を持たせる。ThemeとDiscipline（学問分野）は別の一覧として管理する。
- EntryGroup（小テーマ）：id、title、themeIds、overviewNodeId（任意）、questionIds、theme別の表示順。これは入口を編集するためのまとまりで、記事自体のノード種類とは区別する。
- questionIdsは記事ノードの不変IDを参照する。リンク先は参照先ノードのslugから生成し、入口ごとにタイトル・URL・本文を重複して持たない。
- EntryGroupは複数Themeに所属できる。公開時はpublishedの参照先だけを表示し、公開先がないグループは展開可能な項目として出さない。
- 表示順、見出し、所属、アイコンの追加・変更はデータで行えるようにする。心理学や宗教の記事追加に、入口コンポーネントの書き換えを要求しない。
構造の例：Theme「mind」→ EntryGroup「consciousness」→ Question「ai-consciousness」。概要記事「意識とは何か」はoverviewNodeIdで参照する。EntryGroup「freewill」はmindとethicsから共通参照できる。
記事本文・検索・関連リンク・関係マップは同じノードと関係データを参照する。画面別に同じ説明をコピーして管理しない。
初期はGit管理のファイルで運用可能。既存環境がなければNext.js＋TypeScriptを候補とし、Vercel運用に合わせる。DB・CMS・認証の選定は後工程で理由を示す。現行公式ドキュメントを確認して実装する。
9. 編集・信頼性
出典を捏造しない。科学・哲学・宗教で根拠の種類を区別。相関を因果として説明しない。学派内部の違いや研究の不確実性を必要な範囲で示す。
著作を長く転載せず、自分の言葉で説明。引用には出典と参照箇所を添える。画像も権利・出典を確認する。
分野横断のつながりは自動生成だけで公開せず、編集確認を通す。更新日時と修正履歴を扱える構造にする。
10. AIの将来仕様
AIはNOEMAP内の公開・確認済みコンテンツを検索して回答。現在のページを明示的な文脈とし、参照ページ・出典を回答に添える。未公開記事・他ユーザーのノートは検索対象にしない。
機能：簡単な説明、別の立場との比較、反論、次の探索先案内。質問文の例だけで機能が使えるようにする。
サイト内の根拠が足りない場合は不足を伝える。存在しない人物・出典・URLを作らない。外部知識を使う場合はサイト内根拠と区別する。
APIキーはサーバー側。入力長・出力長・時間・同時実行・利用枠を制限。無料枠は1日3回を仮案とし、実測後に変更可能とする。日付境界のタイムゾーンを明示。枠の消費・予約・失敗時の返却を原子的に扱い、並列送信で上限を超えない。
応答後に回答・参照ID・モデル・使用量・推定原価を記録。個人データの保存範囲と削除方法を決める。履歴はユーザー単位で隔離。
未接続時はAI入力欄を動作するように見せない。機能フラグで非表示または準備中表示。
11. 収益化
優先は関連書籍の案内と、将来のAI・会話保存・ノートの会員機能。記事と根拠確認は基本無料を推奨。
Prime Studentは学生向け読書・学習ページの補助導線。全ページへの一律表示はしない。設置時にAmazonの現行条件を確認。価格・特典・紹介報酬を本書で確定しない。
広告・アフィリエイトは明示し、ランキングやAI回答を報酬で歪めない。リンク未設定なら仮アフィリエイトURLを公開しない。
会員プランは原価測定後に料金と枠を決定。「完全無制限」を仮実装しない。将来の決済はサーバー側で権限判定し、決済イベントの重複処理に対応。
12. UI・検索・公開品質
落ち着いた読みやすい画面。本文幅を抑え、見出し・表・余白で整理。装飾目的の画像を大量に置かない。画像を作る場合は横長、文字入り画像を避ける。
320px程度のスマホからPCまで本文・表・ナビが破綻しない。表は必要時だけ内部横スクロール。グラフには読み上げ可能なリスト代替を用意。キーボード操作、フォーカス、コントラストを確認。
検索はタイトル・別名・要約を対象にする。ノード種類・テーマ・分野で絞り込み。空結果には別名やテーマ一覧への案内を表示。
SEOはページ単位で題名・説明・正規URL・OG画像・パンくずを設定。公開ページのみサイトマップへ。検索結果ページや個人ページのインデックス方針を分ける。構造化データは実際のページ内容に一致させる。検索順位を保証しない。

14. Phase 1の受入条件
- スマホで大テーマ2列、PCで4列のカードが読める。アイコン・テーマ名・身近な問いが各カードにある。
- 大テーマを押すと、そのカードを含む行の直後に小テーマが開く。
- 小テーマを押すと、その項目の直下に具体的な問いへのリンクが開き、次の小テーマより前に表示される。
- 末端の問いを押すと、実在する個別記事URLへ移動する。追加の展開・確認操作を要求しない。
- 小テーマの概要記事へ直接進める。大テーマから個別記事までは通常3タップまで。
- 同じ項目の再タップで閉じる。同階層の別項目を選ぶと開閉状態が切り替わる。
- 記事の直接URL表示・更新・共有が成立する。戻ると入口の開閉状態と位置が復元される。
- キーボードでも展開とリンクを操作できる。展開はbutton、移動はaまたはLinkとして区別し、展開状態をaria-expanded等で伝える。
- 320px・390px・768px・1280px程度の画面で、入口・展開・記事を確認する。文字や押下領域が見切れず、スマホのタップ直後に変化が分かる。
- 学問分野や記事をデータで追加できる。同一記事を複数テーマから案内しても記事・URLが重複しない。
- ホームから問いに入り、関連人物・概念を経て別の問いへ辿れる。
- 全公開ページに要約・出典・更新日があり、関係に理由が表示される。
- 名前・別名で検索でき、種類・テーマで絞れる。空結果でも探索を続けられる。
- draftが一覧・検索・関連表示・サイトマップに出ない。直接URLも公開されない。
- 存在しない関係先、重複ID・slug、型違反、リンク切れを検出できる。
- スマホで本文・ナビが見切れず、表とグラフに代替表示がある。
- ビルドと型チェックが通り、代表的な探索導線をブラウザで確認する。
- 未接続のAI・課金・保存を利用可能と誤認させない。
- ソース管理と追加記事の運用方法が説明されている。

16. 参考プレビューの扱い
NOEMAP-design-preview.htmlは、今回の最終プレビューを外部で確認できるHTMLとして書き出したもの。色・余白・カード・近くでの展開・末端から記事画面への切り替えを確認する資料として使う。
参考HTMLでは画面切り替えをローカルで模擬している。ハッシュリンク、仮本文、会話表示用のラッパーやアイコン初期化を、そのまま本番のルーティング・記事・アプリ構造に採用しない。実装先のコンポーネント・ルーター・アイコンライブラリを使って再現する。
プレビューのHTML/JavaScript構文と参照要素の整合性は確認済み。実ブラウザの描画・操作、および本番形式の個別URLへの移動は実装先で検証する。プレビューがあることを、実サイトの実装・公開・記事内容の検証完了と解釈しない。
この文書に含むプレビュー用の問いの例は全件制作の要求ではない。まず代表的な導線を完成させ、公開できる記事を確認して増やす。
